# Data

## Layout

- `raw/` holds pinned copies of upstream files. `raw/MANIFEST.tsv` records each file's source repo, commit, path, fetch date and sha256. The `fetch_*` rules in the `Snakefile` download exactly these files from those commits and refuse any file whose sha256 differs. Raw files are never edited. To move a source to another upstream commit, run `scripts/pin_raw.py` (see the comment at the top of the `Snakefile`).
- `manual/` holds small hand-curated tables. Every non-obvious value carries a source.
- `processed/` is generated by scripts and can be deleted and rebuilt at any time.

## Sources

- `raw/beijing-subway-schedule/` is the weekday and weekend train schedule from [BoyInTheSun/beijing-subway-schedule](https://github.com/BoyInTheSun/beijing-subway-schedule) at commit `11aaff2` (2026-01-13). It is CC BY-SA 4.0 (see its `LICENSE`), so derived data in `processed/` carries the same license. It is built from [Mick235711/Beijing-Subway-Tools](https://github.com/Mick235711/Beijing-Subway-Tools).
- `raw/beijing-subway-tools/` is the per-line timetables and `metadata.json5` from the Beijing data directory of [Mick235711/Beijing-Subway-Tools](https://github.com/Mick235711/Beijing-Subway-Tools) at commit `51fc9c9` (2026-10-27), MIT licensed. It has per-station timetables and transfer walk times (`metadata.json5`). Model A doesn't use it yet.
- `manual/lines.csv` gives line codes, English names, expected shape and fare group. The four separately fared lines (both airport expresses, Xijiao, Yizhuang T1) come from the Fares section of the English Wikipedia article on the Beijing Subway: transfers to or from them require a new fare, so a single-ticket run cannot use them.
- `manual/loop_closures.csv` gives the run time of the one segment of Lines 2 and 10 that no train in the snapshot crosses (the source splits each lap there). Values are `loop_last_segment` from Beijing-Subway-Tools at commit `51fc9c9`.

## Model A (`processed/model_a/`)

Built by the `build_model_a` rule in the top-level `Snakefile` (`snakemake -c1`).

Standard library only, Python 3.10+. Output is sorted and byte-identical across runs.

- `stations.csv`: one row per station. A station is identified by its Chinese name, so same-named stops on different lines are one vertex. IDs (`S001`...) follow Unicode order of the name, so they can shift when stations are added. `on_network_fare` is 0 for stations served only by separately fared lines.
- `lines.csv`: line metadata, station count and number of weekday trains.
- `line_stations.csv`: first and last weekday departure per line, direction and station. Times after midnight are written as `24:xx`.
- `edges_directed.csv`: one row per line and direction between adjacent stops, with mean, median, min and max run time over all weekday trains. A run time is the difference between scheduled times at consecutive stops, so it includes one dwell. Schedule times are whole minutes, so the mean is the better estimate.
- `edges.csv`: the model A edges, one per line and station pair. `weight_min` is the mean of the two directions. Three station pairs are linked by two lines (花庄–环球度假区 on Lines 1 and 7, 金安桥–苹果园 on Line 6 and S1, 西二旗–清河站 on Line 13 and Changping); both rows appear, so collapse to the minimum for a simple graph.
- `build_report.md`: shape checks per line, totals, widest run-time spreads, and problems found.

How the schedule's special entries are handled: Line 6 overtaking trains pass some stations without stopping (`(07:42`). Those hops are not used for timing or adjacency. Trains held for an overtake have two entries at one station (`07:40-` then `07:43`). The arrival is used for the inbound hop and the departure for the outbound hop, so the wait is left out.
